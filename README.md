# tt-mecenate
Тестовое задание 1 - Mecenate

Платформа: iOS + Android (React Native + Expo)

## Структура проекта

```
src/
├── app/                   # Слой приложения (Screen-based)
│   ├── _layout.tsx       # Корневой layout с навигацией
│   └── index.tsx         # Главная страница
│
├── entities/             # Бизнес-сущности (domain layer)
│   └── post/             # Сущность "Пост"
│
├── features/             # Фичи (features layer)
│   └── feed/             # Фича "Лента публикаций"
│
└── shared/               # Общие компоненты и утилиты
    ├── api/              # API-слой (Axios, запросы к бэкенду)
    └── ui/               # UI-компоненты и дизайн-токены
```

### Описание слоёв

**app/** — слой, ориентированный на страницы и роуты. Содержит layout-файлы для React Navigation и структуру, близкую к URL-адресам.

**entities/** — бизнес-сущности (Post, User и т.д.). Здесь описываются типы, хелперы и логика, связанная с доменными объектами. Находится на одном уровне с features и app, чтобы подчеркнуть их независимость от слоя представления.

**features/** — фичи (features), представляющие собой законченные пользовательские сценарии (Feed, Profile, Settings и т.д.). Каждая фича может использовать несколько сущностей и компонентов из shared. Находится на одном уровне с entities и app.

**shared/** — общие компоненты, которые могут использоваться в разных частях приложения:
- **api/** — клиент для взаимодействия с бэкендом (Swagger-генерированные запросы)
- **ui/** — переиспользуемые UI-компоненты и дизайн-токены

Задача

Разработать экран ленты публикаций для платформы Mecenate — сервиса поддержки
авторов (аналог Patreon/Boosty).
Пользователь открывает приложение и видит список постов от авторов, на которых
подписан.

Что нужно реализовать

Экран Feed (лента)
● Список постов: аватар автора, имя, превью текста, обложка поста, счётчик лайков и
комментариев
● Пагинация — курсорная (подгрузка при скролле вниз)
● Pull-to-refresh
● Закрытый пост (tier: "paid") — показывать заглушку вместо текста
● Сообщение об ошибке если API недоступен: «Не удалось загрузить публикации»
с кнопкой повтора

## ROADMAP

### День 1 — основа проекта и архитектура.
Поднять Expo + TypeScript, подключить React Navigation, MobX, TanStack Query, Axios, дизайн-токены и базовую структуру папок. API-слой под Swagger. UI-kit: компонениты и дизайн токены. Прикрутить линтер, прекоммитхук. В README не забудьте писать инструкции по старту проекту. 

***Критерии готовности***
	- [ ]   Приложение запускается в Expo GO
	- [ ]	Есть навигация (минимум 1 экран)
	- [ ]	React Query работает (есть тестовый запрос)
    - [ ]   Готовы базовые компоненты и дизайн токены дизайн системы. 
    - [ ]   Невозможность запушить грязный код.
    - [ ]   Архитектура отражена в структуре проекта и документации.

### День 2 — экран Feed.
Сделать список постов. Реализовать курсорную пагинацию через useInfiniteQuery. Добавить Обновление постов, фильтр. Платные посты не отображать, заглушка вместо них. 

***Критерии готовности***
	- [ ]	Скролл подгружает новые данные
	- [ ]	Нет дублей в списке. UI не прыгает, двигаться плавно. 
	- [ ]	Pull обновляет данные
	- [ ]	Фильтр меняет отображение постов. 

### День 3 — доработка Feed
Закрыть ошибочные состояния, текст ошибки должен совпадать с ТЗ, с кнопкой повтора, которая работает корректно. Проверить, что пагинация не дублирует данные, что фильтр не смешивает посты и то, что при подгрузке ui не дергается. Доработать соответствие интерфейса макету. Провести рефакторинг там, где он целесообразен.

	- [ ]	Ошибка корректно ретраится
